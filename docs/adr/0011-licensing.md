# 0011. Licensing of OKoala and its dependencies

- Status: Accepted, 2026-10-22

## Context

OKoala is licensed AGPL-3.0-only, so that anyone can audit the code and build their own
binaries, and so that hosted modifications stay open. Dependencies must be compatible with
that, and the third-party licence notices must ship with every release. Some useful Rust
crates are MPL-2.0, a file-level copyleft licence compatible with the AGPL when the files
are used unmodified. Outside contributions need a clear licence grant before they are
merged.

## Decision

- OKoala's own code is AGPL-3.0-only. Every source file starts with the copyright line and
  the SPDX identifier, and nothing else.
- Dependencies must be permissive (such as MIT, Apache-2.0, BSD, ISC, Zlib) or MPL-2.0
  used unmodified. `cargo deny` enforces the allowed list in CI.
- Patching an MPL-2.0 dependency needs its own decision record.
- Each release ships a third-party licence file generated by `cargo-about` and from the
  npm dependencies, and an SBOM.
- A contributor licence agreement (CLA) will be required for outside contributions. Its
  text is chosen before the first outside contribution is merged.

## Consequences

- A new dependency with an unlisted licence fails CI until it is reviewed.
- Crates under other copyleft or non-free licences are not used, so a few features may
  need code of our own instead.
- Until the CLA exists, outside pull requests cannot be merged. Issues and security
  reports are welcome ([SECURITY.md](../../SECURITY.md)).

## Alternatives considered

- **Permissive dependencies only, no MPL-2.0.** Rejected: it would exclude maintained
  crates for no licensing benefit when they are used unmodified.
- **A permissive licence for OKoala.** Rejected: a hosted service could then run modified
  code without publishing it.
